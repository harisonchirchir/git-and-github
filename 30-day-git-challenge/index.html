30-Day Git Challenge

Practice Git and GitHub step by step with daily exercises that build confidence through repetition, review, and hands-on problem solving.

How to use this challenge

  1. Pick one day at a time and work in your own practice repository.
  2. Use the commands in each step before checking the solution reference.
  3. Keep your notes in a file such as notes.md or in commit messages.
  4. Repeat the challenge on a second project to reinforce the workflow.

Day-by-day guide

Day 1 — Install and configure Git

Goal: Set up your local Git environment.

  1. Install Git from git-scm.com.
  2. Verify installation with git --version.
  3. Set your name and email:
git --version
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Solution reference: Lab 01 — Introduction to Git and GitHub

Day 2 — Create your first repository

Goal: Learn how Git repositories are initialized.

  1. Create a new folder for a practice project.
  2. Open the terminal and run git init.
  3. Check that the .git folder exists.
mkdir git-practice
cd git-practice
git init
ls -la

Solution reference: Lab 01 — Introduction to Git and GitHub

Day 3 — Track your first changes

Goal: Understand status, add, and commit.

  1. Create a small README.md.
  2. Run git status.
  3. Stage changes with git add.
  4. Commit with a clear message.
git status
git add README.md
git commit -m "Add README for project setup"

Solution reference: Lab 01 — Introduction to Git and GitHub

Day 4 — Write a good commit message

Goal: Practice clear and professional commit wording.

  1. Make 2–3 small changes.
  2. Write a short subject with a clear action.
  3. Describe the reason for the update in the body.
git commit -m "feat: add landing page"
# or
git commit -m "fix: correct login validation error"

Solution reference: Lab 02 — The Ultimate Guide to Writing a Good Commit Message

Day 5 — Use .gitignore

Goal: Prevent files like env secrets and dependencies from being tracked.

  1. Create a .gitignore file.
  2. Add entries such as node_modules/, .env, and .DS_Store.
  3. Commit the file.
touch .gitignore
printf "node_modules/\n.env\n.DS_Store\n" >> .gitignore
git add .gitignore
git commit -m "Add project ignore rules"

Solution reference: Lab 10 — Advanced Git Tools and Repository Management

Day 6 — Inspect Git history

Goal: Understand commit logs and project history.

  1. Run git log.
  2. Use --oneline to keep output concise.
  3. Review authors, dates, and messages.
git log --oneline --decorate --graph --all
git log --oneline -n 5

Solution reference: Lab 05 — Everyday Git

Day 7 — Undo small mistakes

Goal: Restore files safely without losing everything.

  1. Edit a file and save it.
  2. Run git restore to discard the changes.
  3. Practice git revert for a recent commit.
git restore README.md
git revert HEAD

Solution reference: Lab 06 — Undoing and Recovering

Day 8 — Reset vs revert

Goal: Understand the difference between removing a commit and undoing it.

  1. Create a bad or unnecessary commit.
  2. Practice git reset --soft HEAD~1.
  3. Compare the result with git revert HEAD.
git reset --soft HEAD~1
git revert HEAD

Solution reference: Lab 06 — Undoing and Recovering

Day 9 — Branching basics

Goal: Work on feature changes without disturbing the main branch.

  1. Create a new branch.
  2. Commit changes there.
  3. Return to the main branch.
git checkout -b feature/login-page
git checkout main

Solution reference: Lab 04 — Mastering Git Workflows and Merge Conflict Resolution

Day 10 — Merge a branch

Goal: Bring feature work into the main line of development.

  1. Merge a feature branch into main.
  2. Review the commit history.
  3. Confirm the merge is clean.
git checkout main
git merge feature/login-page

Solution reference: Lab 04 — Mastering Git Workflows and Merge Conflict Resolution

Day 11 — Resolve merge conflicts

Goal: Fix conflicts manually and finish the merge cleanly.

  1. Create conflicting edits on the same file.
  2. Open the conflict markers.
  3. Resolve the conflict and commit the result.
git status
git add resolved-file
git commit -m "Resolve merge conflict"

Solution reference: Lab 04 — Mastering Git Workflows and Merge Conflict Resolution

Day 12 — Use Git stash

Goal: Save work temporarily while switching tasks.

  1. Make changes that are not ready to commit.
  2. Run git stash.
  3. Switch branches or continue your work.
  4. Restore with git stash pop.
git stash
git stash list
git stash pop

Solution reference: Lab 06 — Undoing and Recovering

Day 13 — Create and push a GitHub repo

Goal: Connect your local project to GitHub.

  1. Create a repository on GitHub.
  2. Add the remote URL.
  3. Push the branch with git push -u origin main.
git remote add origin git@github.com:YOUR-USER/YOUR-REPO.git
git push -u origin main

Solution reference: Lab 01 — Introduction to Git and GitHub

Day 14 — Clone and inspect a remote repo

Goal: Learn how to work with existing repositories.

  1. Clone a public repository.
  2. Check the remote URL and branches.
  3. Pull the latest changes.
git clone https://github.com/owner/repo.git
cd repo
git remote -v
git pull origin main

Solution reference: Lab 05 — Everyday Git

Day 15 — Fork a repo

Goal: Practice the contribution workflow used in open source.

  1. Fork a repository on GitHub.
  2. Clone your fork locally.
  3. Create a branch and push to your fork.
git checkout -b update-docs
git push -u origin update-docs

Solution reference: Lab 07 — GitHub Collaboration

Day 16 — Open a pull request

Goal: Propose your changes for review.

  1. Push a feature branch to GitHub.
  2. Open a pull request with a title and summary.
  3. Explain what changed and why.
git push -u origin feature-branch

Solution reference: Lab 07 — GitHub Collaboration

Day 17 — Use GitHub issues

Goal: Track tasks and bugs as part of your workflow.

  1. Create an issue.
  2. Write a clear title and description.
  3. Assign labels or link the issue to a pull request.

Solution reference: Lab 07 — GitHub Collaboration

Day 18 — Create tags and releases

Goal: Mark important project milestones.

  1. Create a lightweight or annotated tag.
  2. Push tags to GitHub.
  3. Use a release title and notes.
git tag v1.0.0
git tag -a v1.1.0 -m "Release 1.1.0"
git push origin --tags

Solution reference: Lab 09 — Git Tags, Versioning, and GitHub Releases

Day 19 — Filter commit history

Goal: Search your project history more efficiently.

  1. Use --grep to find commit messages.
  2. Filter by author or date.
  3. Use --stat to see what changed.
git log --oneline --grep "feature"
git log --author "Your Name" --oneline
git log --since="2024-01-01" --oneline

Solution reference: Lab 05 — Everyday Git

Day 20 — Use git blame

Goal: Trace who changed a line and when.

  1. Open a file with historical changes.
  2. Run git blame.
  3. Review the author and commit for each line.
git blame README.md

Solution reference: Lab 10 — Advanced Git Tools and Repository Management

Day 21 — Rebase a branch

Goal: Move your work onto the latest main branch.

  1. Create a feature branch.
  2. Run git rebase main.
  3. Resolve any conflicts and continue.
git checkout feature-branch
git rebase main

Solution reference: Lab 04 — Mastering Git Workflows and Merge Conflict Resolution

Day 22 — Cherry-pick a commit

Goal: Apply one specific commit to another branch.

  1. Find the commit you want to reuse.
  2. Check out the target branch.
  3. Use git cherry-pick.
git log --oneline
git cherry-pick <commit-sha>

Solution reference: Lab 10 — Advanced Git Tools and Repository Management

Day 23 — Work with stashes in more detail

Goal: Temporarily save multiple changes and restore them cleanly.

  1. Modify two files.
  2. Use a named stash with a message.
  3. Switch branches and restore the stash.
git stash push -m "WIP: feature work"
git stash list
git stash pop

Solution reference: Lab 06 — Undoing and Recovering

Day 24 — Practice a clean PR flow

Goal: Make your review-ready branch easy to understand.

  1. Create a feature branch from main.
  2. Keep commits focused and small.
  3. Push and open a pull request.

Solution reference: Lab 07 — GitHub Collaboration

Day 25 — Use a hotfix branch

Goal: Fix a production problem without disturbing your current feature work.

  1. Create a hotfix branch.
  2. Apply the bug fix.
  3. Merge it once reviewed.

Solution reference: Lab 04 — Mastering Git Workflows and Merge Conflict Resolution

Day 26 — Debug with git bisect

Goal: Identify the commit that introduced a bug.

  1. Mark the repository as bad.
  2. Mark a known-good commit.
  3. Use git bisect to isolate the issue.
git bisect start
git bisect bad
git bisect good <good-commit>

Solution reference: Lab 10 — Advanced Git Tools and Repository Management

Day 27 — Add a submodule

Goal: Learn how a repo can include another Git repo.

  1. Initialize submodule support.
  2. Add a repo as a submodule.
  3. Commit the parent repository changes.
git submodule add https://github.com/owner/repo.git vendor/repo

Solution reference: Lab 10 — Advanced Git Tools and Repository Management

Day 28 — Use Git LFS

Goal: Manage large binary files more efficiently.

  1. Install Git LFS.
  2. Track large file types such as *.png or *.zip.
  3. Commit the tracked assets.
git lfs install
git lfs track "*.png"
git add .gitattributes

Solution reference: Lab 10 — Advanced Git Tools and Repository Management

Day 29 — GitHub Actions basics

Goal: Automate a simple workflow after push or pull request events.

  1. Create a workflow file under .github/workflows/.
  2. Run a shell command such as echo or a basic test.
  3. Check the Actions tab after pushing.

Solution reference: Lab 08 — Automating Workflows with GitHub Actions

Day 30 — Final challenge: complete Git workflow

Goal: Simulate a real project lifecycle from start to finish.

  1. Create a project repo and initial commit.
  2. Make several feature branches.
  3. Merge one branch and resolve conflicts.
  4. Open a pull request and review.
  5. Tag the final release.
