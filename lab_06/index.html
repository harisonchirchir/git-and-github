Undoing Changes and Recovering Work

Choose the right recovery command based on whether a change is uncommitted, staged, committed locally, or already shared. Inspect first: some undo operations are destructive.

Step 1: Inspect before undoing

git status
git diff
git diff --staged
git log --oneline --decorate -5

If work might matter, save a copy or create a temporary branch before a risky recovery. Avoid destructive commands if you are unsure which files or commits they affect.

Step 2: Discard or unstage uncommitted changes

Discard working-tree edits to a tracked file:

git restore <file>

This replaces the file with its staged version, or with HEAD if nothing is staged. Discarded edits are not normally recoverable; inspect or back them up first.

Unstage a file while keeping its edits, or unstage all files:

git restore --staged <file>
git restore --staged .

Untracked files are not removed by git restore; review status and delete them intentionally if needed.

Step 3: Undo a commit safely

git revert creates a new commit that reverses an earlier commit. It is usually the safe choice for commits already shared with others:

git revert <commit>
git push

For a merge commit, Git may require a mainline parent, for example git revert -m 1 <merge-commit>. Confirm which parent represents the history to keep.

Step 4: Understand reset

git reset --soft HEAD~1   # Undo last commit; keep changes staged
git reset --mixed HEAD~1  # Undo last commit; keep changes unstaged
git reset --hard HEAD~1   # Discard commit and working-tree changes

Use --soft or --mixed only to rewrite commits that have not been shared. --hard is destructive. Do not reset published history unless the team explicitly coordinates a history rewrite.

Rule of thumb: use restore for file-level uncommitted edits, revert to undo published commits, and reset to reorganize private local history.

Step 5: Temporarily set aside work with stash

git stash push -m "WIP: profile form"
git stash push -u -m "Include new files"
git stash list
git stash show -p stash@{0}
git stash apply stash@{0}
git stash drop stash@{0}

apply keeps the stash entry; pop applies it and removes the entry if successful. Stash is temporary storage, not a long-term backup—commit important work.

Step 6: Recover a lost commit with reflog

git reflog
git show <commit>
git branch recovery <commit>

Find and inspect the commit in the local reflog, then create a recovery branch before restoring work. Reflog entries expire over time and are not a substitute for backups.

Practice: choose the right recovery

  1. Edit a file and discard one unwanted edit with git restore.
  2. Stage a file, then unstage it while preserving the edit.
  3. Make a local commit and undo it with git reset --soft HEAD~1.
  4. Push a test commit and reverse it with git revert.
  5. Stash an edit, switch branches, and restore the stash.
  6. Inspect git reflog and explain how a recovery branch protects a dangling commit.
